# 论证稳定性沙盘（Argument Stability Sandbox）

一个用于构建和检验论证网络的 Web 应用。用户可以创建**观点**与**证据**节点，拖拽连线标记为**支持**或**反驳**并设置权重；系统会从节点初始可信度出发，在允许有向环的图上进行同步迭代传播。收敛后显示最终可信度；若检测到持续振荡，则停止计算并高亮导致振荡的负反馈环。每次计算后还可用**传播回放**逐轮回看：画布按当轮可信度着色、显示相邻轮升降，选中节点可核对下一轮值的完整分解。此外还提供**边权敏感性扫描**：选择一条连线与一个目标节点后，服务端在不保存图的前提下把该边权从 0 到 1 等距取 21 个值分别计算，前端以曲线展示目标节点的最终可信度，并标出首次跨过 0.5 的阈值区间。最后提供**影响路径追踪**：选择一个目标节点和起始证据后，服务端枚举至多 8 跳的有向简单路径（遇重复节点立即截断以避免环），按支持/反驳符号与边权的乘积计算路径影响分数，返回绝对影响最大的前 3 条路径及其净符号，并在画布上高亮选中路径。还提供**一键整理布局**：可锁定任意节点位置并先预览整理结果（压缩强连通分量为 DAG、最长路径分层、4 轮重心排序、分量内节点绕中心排圆），确认后才一次性应用并保存。

## 唯一启动命令

确保已安装 Docker Engine 与 Docker Compose Plugin，然后在项目根目录执行：

```bash
docker compose up --build
```

启动成功后访问：

- 地址：<http://localhost:8080>
- 端口：容器内固定 `8080`，宿主机默认映射 `8080:8080`

后台运行可使用：

```bash
docker compose up --build -d
```

停止并保留 SQLite 数据：

```bash
docker compose down
```

容器内置了基于 `GET /api/health` 的健康检查，可用以下命令查看状态（`healthy` 即服务就绪）：

```bash
docker compose ps
```

## 必要配置

通常无需任何配置。只有想改变宿主机访问端口时，复制 `.env.example` 为 `.env` 并修改：

```env
APP_PORT=8080
```

例如改为 `APP_PORT=3000` 后访问 <http://localhost:3000>。

其他运行时环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 容器内 HTTP 端口，一般不需要修改 |
| `DATABASE_PATH` | `/app/data/argument.db` | SQLite 数据库文件路径 |

数据保存在 Docker named volume `argument-sqlite-data` 中。应用首次启动会自动创建数据库、表结构以及一张空白图；镜像构建阶段已经安装全部前后端依赖并完成构建。

## 使用指南

1. 点击顶部 **＋ 观点** 或 **＋ 证据** 创建节点。
2. 从节点右侧连接点拖到另一个节点左侧连接点创建连线。
3. 点击节点，可编辑名称、类型、初始可信度（0–100%）以及是否固定。
4. 点击连线，可在“支持 / 反驳”之间切换并调整权重。
5. 点击 **运行稳定性分析**：
   - 绿色状态表示达到收敛阈值；
   - 红色状态表示持续振荡或达到上限仍明显不稳定；
   - 节点显示最终可信度及相对变化；
   - 振荡时红色脉冲节点与加粗红色边标出负反馈环。
6. 计算完成后，画布左下角出现**传播回放**控制条（详见下节）。
7. 使用 **导出 JSON** 保存当前图，使用 **导入 JSON** 恢复。
8. 可先载入“稳定示例”或“振荡示例”观察两种结果。
9. 在右侧**边权敏感性扫描**卡片中选择一条连线与一个目标节点，点击 **运行边权扫描**（详见下下节）。
10. 在右侧**影响路径追踪**卡片中选择起始证据、目标节点与最大跳数（1–8，默认 8），点击 **运行路径追踪**（详见下节）。在画布上点击证据节点会自动设为起点，点击观点节点会自动设为目标。
11. 点击节点后在检查器勾选「📌 整理布局时锁定此节点位置」可锁定任意节点；点击顶部 **🧭 一键整理布局** 生成预览（详见专节），确认后才会写入画布并自动保存。

## 传播回放

每次计算完成后，画布左下角的回放条可回看**第 0 轮（先验）到停止轮**的完整过程：

- **迭代滑杆**：拖动即可跳到任意轮次。画布按该轮可信度为节点着色（红 → 黄 → 绿），节点内的数值、色条同步更新，并显示相对上一轮的升降（▲/▼ 或“持平”）。
- **播放 / 暂停**：点击 **▶ 播放** 从当前轮逐轮前进（约每 0.8 秒一轮）。收敛结果播到停止轮自动停下，再按一次从第 0 轮重播；振荡结果则按检测到的周期在最后一个周期内**循环播放**（控制条上显示“周期 N 循环”徽标）。
- **下一轮值分解**：计算后点击任意节点，侧栏会展示「当前轮 → 下一轮」的可核对分解：
  - 先验 p 与本次计算实际使用的 λ；
  - 每条入边的有符号贡献（支持为正、反驳为负，即 ±权重 × 源节点当轮值）及其合计；
  - 裁剪前的值 `p + λ·Σ`；
  - 0..1 裁剪量（超出上界裁去多少 / 低于下界抬升多少 / 未裁剪）；
  - 底部核对行：前端用同一公式独立重算，与服务器记录的下一轮值逐位比对，显示“✓ 一致”。
  - 若当前已停在最后一轮，则展示最后一次迭代的分解。
- **固定节点**：分解卡片会明确显示其值由先验锁定（🔒），入边不参与计算，因此**不列出任何入边贡献**，不伪造数据。
- **无副作用**：拖动滑杆、播放、暂停都只是前端视图切换——不会修改图、不会触发重新计算或自动保存；回放状态不写入 SQLite，刷新页面后自然消失（图本身仍会持久化）。
- 任何图编辑（增删节点/连线、改权重等）都会使本次计算结果与回放失效，需重新运行分析。

## 边权敏感性扫描

右侧栏的**边权敏感性扫描**卡片用于检验单条边权变化对某个节点结论的影响：

1. 在「扫描连线」下拉中选择一条连线（在画布上点选某条连线会自动带入，并默认把该连线的目标节点作为扫描目标）；
2. 在「目标节点」下拉中选择要观察的节点；
3. 点击 **运行边权扫描**。服务端把该边权从 **0 到 1 等距取 21 个值**（0、0.05、…、0.95、1），对每个取值在内存中复制一份图、**沿用当前传播参数**（收敛阈值 / 最大迭代 / λ）独立计算，**整个过程不保存图、不写 SQLite、不影响画布**。

曲线说明：

- 横轴为被扫描边的边权，纵轴为目标节点的最终可信度（0–1）；0.5 处有虚线判定线。
- 三类采样点用不同标记分开：**● 收敛**（蓝色实心圆，点之间连成实线曲线）、**◆ 振荡**（红色空心菱形）、**■ 达到上限**（橙色空心方块）。振荡点与上限点没有可信终值，单独落在曲线下方的“无值”刻度上，**不参与连线**。
- **阈值区间**：在连续的收敛采样点之间，目标值首次从 0.5 的一侧跨到另一侧时，用蓝色色带标出该相邻采样区间（如边权 0.35–0.40），并在图下注明两端数值。振荡点或未收敛点会打断连续性，**绝不参与跨越判断**——即便它们的末轮值碰巧越过 0.5 也不会产生阈值区间。
- **悬停点位**（触屏可点击、键盘可聚焦）显示：边权、状态（收敛 / 振荡 / 达到上限）、停止轮次和目标值；振荡或上限点无目标值时，改为显示原因（例如“第 N 轮检测到周期约为 2 的持续振荡……不参与 0.5 跨越判断”）。
- 扫描只依赖请求时的画布与参数；任何图编辑或传播参数修改都会使上次曲线失效，重新选择并运行即可。扫描结果不持久化，刷新页面后消失。

## 影响路径追踪

右侧栏的**影响路径追踪**卡片回答“某条证据通过哪些论证链条影响目标结论、影响方向与强弱如何”：

1. 在「起始证据」下拉中选择一个证据节点（在画布上点击证据节点会自动带入）；
2. 在「目标节点」下拉中选择要观察的节点（在画布上点击观点节点会自动带入；起点与目标不能相同）；
3. 可选「最大跳数」1–8，默认 8；点击 **运行路径追踪**。

服务端在请求携带的当前画布图上进行枚举，**只在内存中计算，不保存图、不写 SQLite、不影响画布**：

- **路径模型**：沿有向边做深度优先枚举，深度不超过最大跳数；一条边的符号贡献为支持边 `+weight`、反驳边 `-weight`，路径影响分数 = 路径上各边带符号边权的**乘积**。因此偶数条反驳的路径为**净支持**（分数为正，含 0 条反驳），奇数条反驳为**净反驳**（分数为负）。
- **截断规则**：扩展下一跳时，若该节点已在当前路径上出现则**立即截断**，因此返回的都是无重复节点的简单路径，任何有向环（含自环）都不会进入结果；抵达目标节点的分支也不再经过目标继续延伸。
- **返回结果**：按路径影响分数的**绝对值降序**取前 3 条（同分时跳数更短、节点序列字典序更小者优先）。侧栏依次展示每条路径的排名、净符号徽标、分数与 `|分数|`、跳数、反驳边数，并用链式标签列出**节点标签与逐边关系**（支持/反驳 + 边权百分比；悬停每一跳可看到截至该跳的累计带符号乘积）。
- **画布高亮**：点击侧栏中的某条路径（默认高亮第 1 条），画布上该路径的连线加粗、流动动画并显示累计乘积，起点节点标「起点」徽标、目标节点标「目标」徽标、途经节点整体描边高亮；再次点击可在 3 条路径之间切换。
- 稠密图上简单路径组合爆炸时，枚举设有遍历预算；达到预算会停止并在结果中提示「枚举已截断」，已找到的路径仍然按绝对值排序返回。
- 追踪结果只依赖请求时的画布；**任何图编辑（增删节点/连线、改标签/权重/关系等）或传播参数编辑都会清空追踪结果与高亮**，重新运行即可。结果不持久化，刷新页面后消失。

## 一键整理布局

顶部工具栏的 **🧭 一键整理布局** 用于把杂乱画布整理为左→右的分层图。整个功能在**浏览器本地**完成计算，预览阶段不发起任何请求：

1. （可选）点击节点，在检查器勾选「📌 整理布局时锁定此节点位置」。锁定节点会显示「📌 位置锁定」徽标，可锁定任意多个。
2. 点击 **🧭 一键整理布局**，画布立即进入**预览态**（节点虚线描边、禁止拖拽与连线），顶部横幅展示整理前后的对比：
   - **连线交叉数**（边取节点左/右连接点，按线段严格相交统计，共端点不算）；
   - **总位移**（所有未锁定节点移动的欧氏距离之和，单位 px）。
3. 点击 **确认应用并保存** 才会一次性把预览坐标写入画布，并沿用既有自动保存逻辑（`PUT /api/graph` 写入 SQLite）；点击 **取消（不改写画布）** 或按 **Escape** 都不会改动画布——取消既不改写画布也不写 SQLite。预览态下禁止拖拽、连线与删除操作。

布局算法（纯前端、确定性，同一输入结果一致）：

- **SCC 压缩**：先用迭代 Tarjan 求有向图的强连通分量，把每个分量压缩为一个节点得到 DAG；
- **最长路径分层**：DAG 上按拓扑序做最长路径分层（`rank = max(rank[前驱]) + 1`），每层为一列，边整体从左指向右；
- **4 轮重心排序**：固定执行 4 轮、每轮一遍正向（按后继重心）一遍逆向（按前驱重心）的稳定重心排序以减少跨层连线交叉；含锁定节点的分量在层内的槽位始终固定，只重排可移动分量；
- **分量内圆排**：同一强连通分量（多于 1 个节点）内的未锁定节点围绕分量中心排成圆（半径保证相邻节点不重叠，并选取使总位移最小的起始旋转角）；单点分量直接取分层中心；
- **锁定锚点**：锁定节点坐标**完全不变**（逐位保留，含缩放层级），其所在分量的中心取锁定节点中心，并作为相邻层的列坐标与纵向锚点；含锁定节点的层，列 x 取该层锁定 x 均值，层间线性插值、外侧等距延伸；
- **去重叠**：最后对全部未锁定节点做迭代推离 + 螺旋空位兜底，保证未锁定节点之间、未锁定与锁定节点之间都不重叠且留有间隙；两个锁定节点之间允许重合；所有输出坐标都必须是有限数（含非有限输入兜底）。

**预览失效**：预览只对生成时的图有效——任何图编辑（增删节点/连线、拖拽、改标签/权重/关系、切换固定或位置锁定、导入 JSON、载入示例等）都会立即丢弃预览并恢复当前真实画布；锁定标记会随图一起持久化到 SQLite（节点字段 `layoutLocked`），刷新后仍然有效。整理布局本身不影响传播计算结果与回放。

## 传播模型

设节点 $i$ 的先验可信度为 $p_i$，当前可信度为 $b_i$，则每轮同步更新：

\[
b_i^{(t+1)} =
\operatorname{clip}_{[0,1]}\left(
p_i + \lambda\left(
\sum_{e:j\to i,\ support} w_e b_j^{(t)}
-
\sum_{e:j\to i,\ rebut} w_e b_j^{(t)}
\right)\right)
\]

- `λ`：传播强度，默认 `0.8`；
- 支持边提高目标可信度，反驳边降低目标可信度；
- 被标记为“固定”的节点始终保持初始可信度；
- 当最大节点变化小于收敛阈值时判定收敛；
- 系统比较最近若干轮的状态向量，发现稳定周期即判定振荡；
- 振荡检测后枚举有向简单环，优先报告具有奇数条反驳边、负增益较强且近期仍在移动的环。

这是一个带先验锚定的线性加权意见传播模型。强负反馈环（例如全强度的三角相互反驳）会产生持续周期；先验与默认传播强度通常会让常规论证图稳定。

## JSON 格式

导出的文件结构如下：

```json
{
  "version": 1,
  "name": "我的论证图",
  "nodes": [
    {
      "id": "e1",
      "label": "实验证据",
      "kind": "evidence",
      "initialBelief": 0.8,
      "anchored": false,
      "layoutLocked": false,
      "position": { "x": 100, "y": 80 }
    }
  ],
  "edges": [
    {
      "id": "edge-1",
      "source": "e1",
      "target": "c1",
      "stance": "support",
      "weight": 0.7
    }
  ]
}
```

约束：

- `kind` 只能是 `claim` 或 `evidence`；
- `stance` 只能是 `support` 或 `rebut`；
- `initialBelief` 与 `weight` 必须在 `0..1`；
- `layoutLocked` 为可选布尔值（缺省视为 `false`），表示一键整理布局时是否锁定该节点坐标，随图持久化；
- 节点 id 必须唯一，连线两端必须引用已存在节点；
- 导入时后端会进行严格校验并返回明确错误。

## HTTP API

- `GET /api/health`：健康检查；
- `GET /api/graph`：读取当前图；
- `PUT /api/graph`：整体替换并持久化当前图；
- `POST /api/propagate`：在当前持久化图上运行传播。响应中的 `result.traces` 记录每个节点第 0 轮到停止轮的逐轮可信度（传播回放的数据来源），`result.options` 为本次实际使用的传播参数。
- `POST /api/sensitivity/edge-weight`：边权敏感性扫描。请求体必须携带当前画布图 `graph`，服务端仅对其做严格校验并在**内存**中逐点计算，**不会保存或修改持久化图**；另外携带 `edgeId`、`targetNodeId`、`options` 与可选的 `samples`（默认 21，范围 2–101）。响应 `scan.points` 为每个等距边权一个点，含 `weight`、`status`（`converged` / `oscillating` / `limit`）、`iterations`、`targetValue`（振荡点为 `null`，原因见 `reason`）、`detectedPeriod`、`maxChange`；`scan.thresholdBand` 为首个由两个相邻收敛点构成、目标值首次跨过 0.5 的区间（无则为 `null`），振荡/未收敛点不参与判断。
- `POST /api/trace/influence-paths`：影响路径追踪。请求体必须携带当前画布图 `graph`（严格校验后仅在**内存**中枚举，**不会保存或修改持久化图**）、起始证据节点 `startNodeId`（其 `kind` 必须为 `evidence`）、目标节点 `targetNodeId`（不得与起点相同），以及可选的 `maxHops`（默认/上限 8，范围 1–8）。响应 `trace.paths` 为按 `absoluteScore` 降序的至多 3 条路径：每条含 `nodeIds` / `edgeIds` / `hops`、逐边 `steps`（`edgeId`、`sourceId`、`targetId`、`stance`、`weight`、截至该跳的 `runningScore`）、路径总分 `score`（支持边 `+weight`、反驳边 `-weight` 的乘积）、`absoluteScore`、净符号 `sign`（`support` / `rebut`）与 `rebutCount`；`trace.enumeratedPaths` 为遍历预算内抵达目标的简单路径总数，`trace.truncated` 表示是否因预算上限提前截断。

示例：

```bash
curl -X POST http://localhost:8080/api/propagate \
  -H 'Content-Type: application/json' \
  -d '{"options":{"threshold":0.001,"maxIterations":200,"lambda":0.8}}'
```

```bash
curl -X POST http://localhost:8080/api/sensitivity/edge-weight \
  -H 'Content-Type: application/json' \
  -d '{
    "graph": {"version":1,"nodes":[],"edges":[]},
    "edgeId": "edge-e1-c1",
    "targetNodeId": "c1",
    "options": {"threshold":0.001,"maxIterations":200,"lambda":0.8},
    "samples": 21
  }'
```

```bash
curl -X POST http://localhost:8080/api/trace/influence-paths \
  -H 'Content-Type: application/json' \
  -d '{
    "graph": {"version":1,"nodes":[],"edges":[]},
    "startNodeId": "e1",
    "targetNodeId": "c1",
    "maxHops": 8
  }'
```
